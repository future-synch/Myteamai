W11 applicant matching criteria playbook
Playbook Captured from chat session · Claude Sonnet · Saved by Curtis · 4 min ago
Playbook steps
1
Hard filter first — Python only
Budget must be ≥ property price × 0.95. Bedrooms must be within stated min/max range. Applied before any AI call.
2
Must-have features are non-negotiable
If applicant listed garden, parking, or quiet as must-have, properties without these are excluded regardless of score.
3
Financing strength weights the score
Cash buyer always scores higher than AIP. AIP held scores higher than mortgage required. AIP pending = flagged.
4
KYC status is separate from match score
KYC-incomplete applicants are returned in results but flagged as can_progress: false. They cannot proceed to offer.
5
Top 3–5 results with rationale
Each result includes a plain-English match reason. Rationale stored here for reference across sessions.
Context note
Derived from the Match Applicants session on 14 Ladbroke Road W11 (Apr 22). The 2-stage logic — Python hard filter then Claude scoring — was confirmed as the preferred approach after the earlier valuation session showed that AI-only filtering produced too many near-misses on budget. This playbook is loaded automatically whenever Match Applicants runs.
